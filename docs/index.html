Skills pile up.
Claude doesn’t notice.

      
The author’s machine has 131 skills across project, user, plugin, app and built-in scopes. A skill that is installed but never loaded is a cost with no return. skill-router fixes that with a single decision at the start of every session.

    

    

      

        
Step 1

        
The session opens

        
A SessionStart hook tells Claude to infer your goal from the first message, or to ask exactly one question if it can’t.

      

      

        
Step 2

        
One Jev call

        
Claude runs skill-router intent set "…". Every installed skill is ranked against the goal in a single call, in about 350 ms, for roughly $0.0004.

      

      

        
Step 3

        
Then nothing

        
One of three answers, relayed once. No per-prompt nagging. If you pivot, you type /intent <new goal> yourself.

      

    

  






  

    

      
Three answers. Never a fourth.

      
Jev returns a calibrated probability for every skill plus a “does any skill help at all” signal. Thresholds on those numbers, not prose, pick the outcome.

    

    

      
A
Load these
Relevant installed skills, named with their probabilities. Claude loads them when the work starts.

      
B
Search skills.sh
Nothing installed fits. Claude is pointed at the find-skills skill, with no candidates pre-seeded, so its own quality filter does the work.

      
C
No skill needed
General assistance is fine. The tool says so once and stays quiet for the rest of the session.

    

  






  

    

      
Measured, not promised.

      
Evaluated 2026-09-17 against real Jev with 131 installed skills. None of the prompts named the expected skill. The harness and cases ship in the repo, so you can re-run it against your own catalog.

The one outcome-A miss was firecrawl-scrape ranked first at 0.81 but gated to “no skill” by a low needs-a-skill probability, a threshold question tracked openly in the repo. The one outcome-B miss routed a Remotion goal to an installed skill whose description explicitly lists Remotion, which is correct by that skill’s own claim.

  






  

    

      

        
Why a decision model, not a chat model.

        
An LLM classifier needs a prompt, writes prose, and has to be parsed. Its “confidence” is whatever it typed. Jev, from TypeSafe AI, answers typed questions with a probability for each of up to 255 options in one parallel evaluation. It never returns a malformed answer and costs two orders of magnitude less.

        
A probe on this catalog confirmed it matches meaning, not words.

0.92

0.00

Install in 60 seconds.

      
Python 3.12 and uv. No key? Everything runs in a clearly labelled mock mode, including the tests and the eval.

    

    

      
Get it

      
$git clone https://github.com/ninjacoder13/skill-router && cd skill-router && uv sync

      
Add your TypeSafe key from console.typesafe.ai · the key is sent only to api.typesafe.ai

      
$cp .env.example .env

      
Register the hook for this project · add --settings ~/.claude/settings.json to do it for every project

      
$uv run skill-router install-hook --write

      
Recommended for outcome B lets Claude search skills.sh with a quality filter

      
$npx skills add vercel-labs/skills --skill find-skills -g

    

  






  

    

      
What it is not.

      
The cut list is part of the product. Each of these was considered and rejected for a reason.

    

    

      
✕
Not per-prompt
v0.1 ran on every prompt. It scored 10/10 on the eval and was still noise: once a session was about skills it suggested skill-creator four prompts in a row. Kept as an opt-in.

      
✕
Not an installer
It prints the npx skills add command and tells Claude to ask you. It never installs anything on its own.

      
✕
Not a thumb on the scale
When nothing installed fits, it hands off to find-skills without pre-seeding candidates, so that skill’s install counts and source reputation decide.

      
✕
Not a service
The catalog is what is on your disk. No server, no telemetry. It never blocks or crashes a Claude Code session; that invariant has its own test.
